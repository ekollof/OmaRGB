OmaRGB Wiki Devices Engines Extending From Omarchy Source

Engines

install.sh installs a painter's packages only when this machine has a device that uses that engine. The list is share/painters.toml. An engine with no package there needs nothing from the package manager. omargb plan shows the match and does not paint.

vanguard_k08

The Sound BlasterX Vanguard K08, USB 041e:3126. There is no package. The engine opens the keyboard's hidraw node (/dev/input/by-id/*Vanguard*if01-hidraw) and writes only the LED colour bytes, so the key map stays as the keyboard has it. The process has to be allowed to open that node. The gradient runs side to side across the key columns.

openrgb

When a matched device uses this engine, install.sh installs the Arch package openrgb. OmaRGB then talks to the server on 127.0.0.1:6742. The package ships openrgb.service, which runs openrgb --server. install.sh does not enable that service. Start it if nothing is already listening:

sudo systemctl enable --now openrgb.service

A keyboard the server reports, with a per-LED mode and more than one LED, is painted with no database row. The gradient runs left to right, one colour per column when the keyboard has a matrix. A mouse, a memory stick, a motherboard, or a hub needs a row. A device with one LED, or without a per-LED mode, gets one theme colour. If the mode has a brightness range, that brightness is set to its maximum.

openlinkhub

Corsair hubs, in this database the Commander PRO. When that device is present, install.sh installs the AUR package openlinkhub-bin and enables openlinkhub.service. The service listens on 127.0.0.1:27003. OmaRGB posts one theme colour to /api/color/all, the same call the web UI uses for every hub device. The openlinkhub binary panics if you run it yourself outside that service. If the service is down, the Commander PRO row falls back to OpenRGB and one Static colour.

asus_rog

An ASUS ROG laptop keyboard, matched the same way as omarchy-hw-asus-rog. install.sh installs asusctl. The paint is one theme colour:

asusctl aura effect static -c RRGGBB

framework16

A Framework Laptop 16 keyboard, matched the same way as omarchy-hw-framework16, including USB 32ac:0012. install.sh installs qmk-hid and, when the rule is not already there, copies Omarchy's unprivileged hidraw rule to /etc/udev/rules.d/50-framework16-qmk-hid.rules. The paint is one theme colour: effect 1, hue, saturation, brightness 100, and save. Hue and saturation follow colorsys.

homeassistant

There is no package. Lamps come from ~/.config/hass.cfg, the same file wallpaperctl uses when that package is installed. OmaRGB does not create the file. It has to be readable only by its owner. A mode such as 644 is rejected and the lamps stay as they are.

install -m 600 /dev/null ~/.config/hass.cfg
[auth]
server = http://127.0.0.1:8123
token = replace-with-a-long-lived-access-token
lamp = light.kitchen, light.desk

server is the Home Assistant base URL, with no path on the end. token is a long-lived access token from your profile in Home Assistant. lamp is a comma-separated list of entity ids. Each id is a domain, a dot, and a name made of letters, digits, and underscores, such as light.kitchen. Anything else in that list is ignored.

The database row bus = "hass", id = "light.*" matches those lamps. A lamp is painted only when it is already on: OmaRGB calls light.turn_on with rgb_color. A lamp that is off stays off. The colour is one theme stop. The bar chooses which stop (warmest, least blue, most saturated, coolest, or brightest). Warmest is the default, so a blue stop does not win. omargb plan lists the lamps and does not call Home Assistant.

Do not commit hass.cfg or the token. If omargb apply reports rejected the config (permissions), run chmod 600 ~/.config/hass.cfg. If it reports config missing, the file, the [auth] section, or one of server, token, and lamp is absent.
