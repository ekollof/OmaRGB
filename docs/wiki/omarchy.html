From Omarchy

OmaRGB does not edit Omarchy. install.sh puts shims first on PATH at the next graphical login, and a theme-set hook paints before that login. The stock commands still exist. They no longer get there first.

What the install takes over

These Omarchy commands become no-ops while the shims are first on PATH. The theme hook runs omargb apply instead.

  • omarchy-theme-set-keyboard
  • omarchy-theme-set-openrgb
  • omarchy-theme-set-keyboard-asus-rog
  • omarchy-theme-set-keyboard-f16

Until that login, Omarchy may paint first and the theme hook corrects it. uninstall.sh removes the hooks and the shims and puts back anything the installer stepped aside.

What is kept

The ASUS and Framework rows use the same machine checks as omarchy-hw-asus-rog and omarchy-hw-framework16.

  • ASUS is sys_vendor ASUSTeK COMPUTER INC. with ROG in the product family. The paint is still asusctl aura effect static.
  • Framework is a Framework machine with Laptop 16 in the product name or family, and the USB id 32ac:0012 the udev rule allows. The paint is still five qmk_hid via calls: effect 1, hue, saturation, brightness 100, and save. Hue and saturation follow colorsys, which is what Omarchy's QMK helper matches.
  • The Framework udev rule is the one Omarchy ships. install.sh copies it when this machine matches.

What is different

The colour is a stop from colors.toml, after the white floor is removed. It is not the raw keyboard.rgb accent.

Omarchy's OpenRGB painter reads that accent, mixes it 40% toward white, and prefers a mode whose name contains "gradient". If the scan fails it falls back to one static broadcast. OmaRGB does not mix toward white and does not broadcast. It talks to the OpenRGB server on 127.0.0.1:6742. A per-key keyboard gets the theme stops left to right. Any other device is painted only when a database row names it, in Direct mode when that device can take a colour per LED, otherwise as one colour.

Home Assistant lamps use the warmest stop by default. The bar can cycle warmest, least blue, most saturated, coolest, and brightest. A lamp that is off stays off.

What is not from Omarchy

  • The Sound BlasterX Vanguard K08 painter. It replaces a local hook, not a mainline Omarchy command, and it writes only the LED bytes in the keyboard's lighting map.
  • OpenLinkHub for the Corsair Commander PRO.
  • Home Assistant. Lamps come from ~/.config/hass.cfg, the same file wallpaperctl uses.
  • The palette watcher. OmaRGB watches colors.toml and keyboard.rgb, so a later rewrite still recolours the hardware. wallpaperctl is a separate package and is not required. It is a recommended way to rebuild that palette from the wallpaper without running omarchy theme set.
